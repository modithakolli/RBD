# RBD++ — Neural Backdoor Audit Suite

> Detect whether a trained ML model has been secretly backdoored — using only a small clean sample and query access to the model.

## What it does

A backdoored model behaves normally on regular inputs but silently misbehaves when a secret trigger pattern appears — e.g. a network-intrusion classifier that waves through malicious traffic carrying one specific feature combination.

**RBD++** audits a trained model for this without ever seeing its original training data. It uses:

1. **Shadow-ensemble comparison** — build populations of known-clean and known-poisoned shadow models, score the suspect model against both, and flag it if it sits closer to the poisoned population.
2. **Reverse distillation** — distil the suspect model into a student network trained only on clean data; large divergence between teacher and student logits indicates hidden backdoor behavior.

The same core idea is then applied to five additional threat surfaces:

| Module | Threat surface |
|---|---|
| `advanced/llm_backdoor.py` | Trigger words in text / LLM prompts |
| `advanced/federated_gatekeeper.py` | Poisoned weight updates in federated learning |
| `advanced/rag_inspector.py` | Injected documents in RAG pipelines |
| `advanced/fingerprinting.py` | Model identity verification |
| `advanced/provenance.py` | Tamper-evident SHA-256 hash-chained audit ledger |

## Quickstart

```bash
git clone https://github.com/<your-username>/RBD-plus-plus.git
cd RBD-plus-plus

python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Place the UNSW-NB15 dataset CSV in data/raw/ (see Dataset section below)

python run_pipeline.py          # attack → detect pipeline (default 2% poison rate)
python run_advanced_audits.py   # LLM / RAG / federated / fingerprint extensions
streamlit run app.py            # view results dashboard
```

A `BACKDOOR DETECTED` verdict on the default run is **correct, expected behavior** — the pipeline both plants and catches the backdoor to demonstrate detection.

## Dataset

The pipeline expects the **UNSW-NB15** network intrusion dataset:

1. Download `UNSW-NB15_1.csv` (or any combined version) from [UNSW Research](https://research.unsw.edu.au/projects/unsw-nb15-dataset).
2. Place it at `data/raw/malware_datset.csv` (note the existing filename spelling — the config handles both).

The raw dataset file is excluded from this repo (`.gitignore`) because of its size (~14 MB). All derived files (`data/poisoned/`, `data/small_clean/`, `models/`, `results/`, `logs/`) are also excluded and regenerated by the pipeline.

## How the detection works

```
Raw data
  │
  ├─ attacks/poisoning.py ──────► poisoned training set (2% trigger-flipped samples)
  │
  ├─ training/train_poisoned.py ► model_W.joblib  ← the "suspect" model
  │
  ├─ training/train_shadow.py ──► shadow/clean/   (MLP + RF + LR on clean data)
  │                               shadow/poisoned/ (MLP + RF + LR on poisoned data)
  │
  ├─ rbd/distillation.py ───────► student_mlp.joblib  (distilled from model_W on clean data)
  │
  └─ rbd/score.py ──────────────► audit_metrics.json
                                   suspicion_score > 0.7 → BACKDOOR DETECTED
```

The suspicion score measures whether the student model's logit outputs sit closer to the poisoned shadow population than to the clean one.

## Known limitations

- Shadow ensembles are small (3 models per class). Larger populations improve reliability.
- The federated gatekeeper module simulates clients on a single machine — it is not connected to a real distributed setup.
- LLM and RAG modules use small synthetic corpora to demonstrate the detection logic; they are not connected to external language models or vector databases.
- The dashboard login is a local demo gate — not a substitute for real access control in a production deployment.
- Detection degrades against random-value triggers that don't have a fixed pattern.
